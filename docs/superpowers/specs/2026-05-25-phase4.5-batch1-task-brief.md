## 2. Why This Batch Comes First

Current project state shows a mismatch between design and runtime behavior:

- `Config.max_tokens` already exists, but `ContextManager` still uses a hardcoded 200k threshold
- `/env` does not expose `max-tokens`
- context compression summary prompt is still Chinese while the system prompt is English-oriented
- `tests/` currently has no usable baseline, which makes later changes hard to trust

This means long conversations can fail before compression triggers, and follow-up architecture work would sit on weak verification.

## 5. Implementation Requirements

### 5.1 ContextManager contract

Target behavior:

- `ContextManager` should be initialized with config-derived token budget
- `should_compress()` should use that budget
- `compress()` should keep current high-level strategy, unless a small fix is needed for correctness

Important guardrail:

- do not introduce a refactor larger than needed
- do not redesign the entire compression model in this batch

### 5.2 Compression message safety

Even though this batch is small, preserve message-structure correctness.

Coding Agent must verify that compression does not obviously break these fields when estimating or preserving history:

- `role`
- `content`
- `tool_calls`
- `tool_call_id`
- `reasoning_content`

Minimum requirement:

- do not regress current handling of `reasoning_content` in token estimation
- do not introduce history shapes that are invalid for subsequent LLM calls

Note:

This batch does not require a full redesign of compression around tool-call pairing, but the implementation should avoid making that risk worse.

### 5.3 `/env max-tokens`

Required behavior:

- command form: `/env max-tokens <value>`
- accepts positive integers only
- invalid values should produce a friendly error without crashing
- successful update should persist through `ConfigStore.save()`

Also update the `/env` help text so the command is discoverable.

### 5.4 `/context` consistency

`/context` should report:

- active model
- active `max_tokens`
- total estimated tokens
- remaining tokens
- compression threshold derived from active config

If `cfg.max_tokens` is invalid or absent, use the same validated fallback path as config loading.
